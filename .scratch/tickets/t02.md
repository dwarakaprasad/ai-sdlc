## What to build

The Curriculum loader and validator, which are a public contract (ADR 0004):
- A written-down markdown format: a Curriculum folder with a top-level `curriculum.md` (district, grade, school year, Curriculum References); one folder per Subject with one file per Term (Unit headings, Lesson sub-headings, a bulleted list of Learning Objectives under each Lesson); and an optional Tutoring Instructions file per Subject.
- A parser that returns either a typed Curriculum tree or validation errors giving file, line and message.
- Stable Lesson keys built from Subject, Term, Unit number and Lesson number.
- The app supports several Curriculum folders.
- A `curriculum:check` command that wraps the same parser and exits non-zero on errors.
- The Parent area lists the loaded Curricula and any validation errors.

## Acceptance criteria

- [ ] The Curriculum markdown format is documented in the repo, using `CONTEXT.md` terms.
- [ ] A valid fixture parses to a Curriculum tree containing Subjects, Terms, Units, Lessons (with stable keys), Learning Objectives and optional Tutoring Instructions.
- [ ] Invalid fixtures (for example a missing `curriculum.md`, a Lesson with no Learning Objectives, a duplicate Lesson number, or a malformed heading) produce clear errors with file and line.
- [ ] `curriculum:check` exits 0 on a valid folder and non-zero with readable errors on an invalid one.
- [ ] The Parent area lists every Curriculum folder found and shows its validation errors.
- [ ] Seam 2 tests (markdown fixtures in, tree or errors out) cover the cases above.
